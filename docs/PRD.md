## 2. 产品背景与定位

### 2.1 背景
大学生群体普遍面临学业压力、人际困扰、未来迷茫与情绪低谷，但校内外心理支持资源有限、预约门槛高，且不少学生存在"不敢求助"的心理负担。一个**随时可用、无评判、可匿名**的对话式心理支持工具，能在"需要倾诉但不敢开口"的时刻提供第一道缓冲。

### 2.2 产品定位
- **纯公益**：不收费、不投放广告、不做商业转化。
- **AI 陪伴 + 安全兜底**：提供温暖的情绪陪伴与疏导，同时具备**风险识别与危机干预**能力；明确自身为"补充"而非"替代"专业心理治疗。
- **长期记忆的"熟人感"**：能记住用户过往对话与情绪，形成持续陪伴感。
- **工程化示范**：在教程型实现上完成安全、并发、数据访问、异常治理的架构级重构，验证 AI 应用的生产工程边界。

### 2.3 不做什么（边界）
- 不做医学诊断，不提供处方药建议。
- 不替代专业心理咨询/精神科治疗。
- 不作为 24 小时紧急救援热线。

## 4. 产品目标与成功指标

### 4.1 目标
1. 让用户在任意时刻获得**流畅、有温度**的心理对话体验。
2. 让 AI 具备**长期记忆**，对话连贯、有"熟人感"。
3. 让系统能**识别情绪与风险**，并在高危时做出干预。
4. 让 AI 回答**有据可依**（RAG 知识库），不空谈。
5. 让系统在真实业务约束下**安全、可控、可运营**。

### 4.2 成功指标（建议）
| 指标 | 说明 |
|---|---|
| 首字延迟 | 流式对话首字 < 2s |
| 对话完成率 | 会话数 / 创建数 |
| 情绪分析覆盖率 | 有用回消息的会话中，成功产出情绪标签的占比 |
| 风险识别召回 | 高危表达中，被规则/模型识别出 riskLevel≥1 的比例 |
| 记忆连贯性 | 同一会话中跨轮次上下文引用正确率 |
| 查询次数稳定性 | 会话列表查询次数恒为 2 次（无 N+1） |

## 5. 核心场景（用户故事）

1. **倾诉**：用户说"最近好累"，AI 先共情、再引导梳理，并给出温和建议。
2. **持续陪伴**：用户隔天回来，AI 记得之前聊过"考研压力"，主动衔接。
3. **情绪追踪**：系统在后台为每条消息打情绪标签，并为会话生成情绪总结（JSON），供展示/风险判断。
4. **高危识别**：用户表达"我不想活了"，系统识别为高危，立即切换危机干预话术并给出求助热线。
5. **知识回答**：用户问"怎么缓解焦虑"，系统检索知识库并给出有依据的建议。

### 7.1 编码与设计规范

> 这一节是「代码质量」的验收标准。功能能跑不算完成，符合下面的规范才算。

| 编号 | 规范 | 说明 |
|---|---|---|
| CODE-1 | **注释用 `//` 行注释，不用 `/** */` 块** | 短、贴着代码；不写“是什么”，只写“为什么”（踩过的坑、反直觉的取舍） |
| CODE-2 | **一个方法只做一件事，禁止方法套方法** | 能一个方法写完的不要拆成 `alignXxx` / `findXxx` 这种小helper链；拆之前的判断标准：这段逻辑是否被复用，且单独可测 |
| CODE-3 | **简单优先，不做多余动作** | 能整数运算就别用浮点 + `Math.ceil`；能一行 `if` 就别引策略模式；没有第二个实现前不抽接口 |
| CODE-4 | 工具类写法 | 无状态工具：`final class` + 私有构造 + 静态方法；不注入 Spring |
| CODE-5 | 纯函数优先 | 判定逻辑（风险、门控、截断）写成无副作用的静态/实例方法，可直接单测，不依赖 Spring 上下文 |
| CODE-6 | 命名即文档 | 类名/方法名要说清“做什么”，不靠注释补齐；缩写只在项目内通用时才用 |

## 8. 情绪与风险设计（关键业务规则）

### 8.1 情绪 JSON 字段（对齐原作者，不可随意改）
`icon / label / keywords / riskLevel / riskDescription / timestamp / isNegative / suggestion / emotionScore / primaryEmotion / improvementSuggestions`

### 8.2 风险等级语义
| riskLevel | 含义 | 处置 |
|---|---|---|
| 0 | 情绪稳定 | 正常对话 |
| 1 | 需要关注 | 温和干预、引导 |
| 2 | 需要心理疏导 | 危机干预话术 + 求助热线 + 事件记录 |

### 8.3 三方融合规则
```
finalRisk = max(关键词规则, 情绪标签映射, 大模型语义判断)
if (isNegative && finalRisk == 0) finalRisk = 1
```
**大模型可升级风险，不可降级风险。** 关键词命中高危词 → 恒为 2。

> 实现约定（已落地）：最终 `riskLevel` 与 `riskDescription` 由 `RiskLevel` 枚举**同源产出**，模型返回的 `riskDescription` 被丢弃；越界等级在 `RiskLevel.fromCode` 收敛到 0/1/2。

### 8.4 数据源原则
- 情绪总结数据源用 **MySQL message 表**（稳定，不被压缩），不依赖 Redis 记忆。
- 情绪只从**用户消息**提取，AI 回复不参与。

## 9. 数据与隐私

- 收集：账号信息、会话内容、情绪标签、会话情绪 JSON。
- 存储：MySQL（业务）+ Redis（记忆/缓存，需设 TTL）。
- 敏感数据：心理对话属高敏感，需加密传输（HTTPS）、访问控制、最小化留存。
- 用户权利（规划）：查看/导出本人数据、注销删除。

## 11. 验收标准（整体）

1. 用户可完成注册 → 登录 → 新建会话 → 流式对话 → 查看历史 全流程。
2. 每条用户消息产生情绪标签；每个会话产生合法情绪 JSON。
3. 高危表达（含隐晦表达）能被识别为 riskLevel≥1，显性高危词恒为 2。
4. 情绪分析/压缩任一失败不影响主对话；服务不因异常崩溃。
5. 非本人无法访问他人会话；登出后 token 立即失效。
6. 会话记忆在跨轮次、跨天（未压缩前）保持连贯。
7. 会话列表分页查询次数固定为 2 次（无 N+1 回归）。
8. 客户端断连时后端能释放资源并记录日志，不抛未处理异常。

## 13. 术语表

| 术语 | 含义 |
